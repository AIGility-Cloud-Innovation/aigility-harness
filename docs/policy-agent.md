# 制度流程管理智能体 · 实现说明

对应业务设计: 《制度流程管理智能体_业务逻辑梳理》(15 个功能模块)。
本文档说明 15 个模块 → aigility-harness 五域架构的落点、已实现范围(POC)、降级策略与二期规划。

## 一、运行方式

```bash
pnpm --filter policy-agent start
# 工作台:      http://127.0.0.1:3430/        (模块表单/智能体对话/台账)
# 审查编排 API: POST /api/review  {"module":"normative","input":{"docNumber":"JT-SJ-2023-003"}}
# 对话 API:    POST /api/chat    {"user_input":"专题梳理: 招标"}
# 台账 API:    GET  /api/kb?op=stats|gaps|list
```

LLM 复用全局配置(`LITELLM_URL/LITELLM_KEY/LLM_MODEL`, 或 `LLM_PROVIDER=bigmodel` + `BIGMODEL_API_KEY`)。
**LLM 不可用时全部模块走规则降级**(`degraded: true` 显式标记), 链路不断——规则链路本身覆盖了
条款切片、四级分层信号、模糊表述四模式、档位连续性、效力维护、统计缺口等核心判定。

## 四、关键设计决策(与业务文档对齐)

1. **条款编号切片是地基**: 解析器不依赖段落缩进/字号, 以 第X条/（一）/1. 为锚点, 直接消除
   "召回片段开头不是完整句子"问题; 附件/表格/无编号块单独进人工队列。
2. **规则打底、LLM 增强、降级兜底**: 每个模块的判定主干(切片/信号/正则/统计)不依赖 LLM;
   LLM 只做语病、归并、机制提炼、冲突判定等增强, 失败即降级并显式标记——审查结论可复现。
3. **不编造**: 依据小库的法规"原文"标注待补录, 合规审查只引名称+条款号+样例场景, 禁止推定条文内容;
   检索不到依据输出"未检索到相关依据"。
4. **人机边界**: 每个 LLM 密集模块的输出都注明"模型产出的是审查线索, 三级审查流程与签发权限在人"。
5. **复用现有组件**: LLM 走 `@cognitive/llm-inference`(litellm/bigmodel); 记忆走 `@cognitive/timem-memory`
   (尽力而为); 闲聊兜底走 `@orchestration/workflow-engine`; 内核经 kernel-dsh/InMemory 双适配。

## 五、二期规划(当前明确不做/做不到的)

| 项 | 规划 |
|---|---|
| Word 批注稿(规范性检查输出形态) | py-bridge → python-docx(docx comments/修订痕迹), 在 aigility Python 侧新增 `@action/docx-edit` 能力 |
| docx/PDF 正文抽取 | py-bridge → python-docx/pypdf, 新增 `@cognitive/doc-parse`; 当前输入为纯文本 |
| 越权判定(模块8) | 待《公司章程》《董事会授权决策事项清单》入库后, 从"权限完整性"升级为"越权比对" |
| 向下转化件条款级比对 | 二期(所属单位数据可信度+管理边界问题), 当前只做转化台账 |
| LangGraph 工作流 | 复杂多步审查流(合规→一致性→分层→意见书)可切 aigilitySDK WorkflowEngine(YAML), 经 py-bridge 热替换 |
| 规章制度系统同步 | 接口打通后替换会话上传入口(增量新增/修订/废止) |
| 检查问题库/风险库 | 到位后作为控制文档第三依据源, 优先级排最前 |
| 向量检索(pgvector) | core 已有 VectorStore 契约, 条款切片(带元数据)即为入库单元; 当前关键词+元数据过滤够 POC |
| 企业微信/OA 推送 | 变动提醒分发渠道扩展(当前会话内+报告) |
