# aigility-harness · 部署坑点与迁移指南

> 记录本项目在本机（Windows）从零启动过程中踩过的坑，供迁移到其他服务器时参考。
> 配套文档：[启动指南.md](./启动指南.md)（本机日常启动用）

## 一、环境安装的坑

### 1. Node.js 用 MSI 安装会卡 UAC
winget/MSI 静默安装会触发 UAC 弹窗，无人值守场景会永久挂起。
**解法**：用官方 zip 便携版（`node-vXX-win-x64.zip`）解压即用，手动加 PATH。

### 2. pnpm install 需要访问私有 Git 仓库
依赖 `@timem/dsh-plugin-timem` 来自私有 Gitea（git.aigility.cloud，GitHub 镜像同样私有），匿名访问 401。
- 必须先装 Git（本机用便携版 PortableGit）。
- 首次拉取时 Git Credential Manager 会弹**凭据助手选择框**（选 manager 并勾选“始终使用”），随后在浏览器弹出 Gitea OAuth 登录页，**需要人工登录一次**，之后凭据缓存到 Windows。
- 无 git 时报错是 `ENOENT not found: git`，容易误判为网络问题。

### 3. PostgreSQL 只剩数据目录、程序被卸载
`D:\DATABASE` 是 PG 15 数据目录，但 `C:\Program Files\PostgreSQL` 曾不存在。
**解法**：重装同大版本（PG 15.x）二进制，用 `pg_ctl -D 数据目录 start` 直接挂载旧数据目录，数据无损。
注意：安装器自建的默认实例服务会占用 5432 并使用**自己的空数据目录**，需停掉并设为手动启动，再挂载旧目录。

### 4. 旧 PG 密码未知时的重置办法（Windows）
1. 备份 `pg_hba.conf`；
2. 在文件顶部临时加一行 `host all postgres 127.0.0.1/32 trust`；
3. **注意用无 BOM 的 UTF-8 写入**（PowerShell `Out-File`/`Set-Content` 默认带 BOM，会导致 PG 报“无效连接类型”拒绝启动，本机踩过）；
4. `pg_ctl reload` 后免密登录，`ALTER USER postgres PASSWORD '...'`；
5. 恢复原 `pg_hba.conf` 并 reload。

## 二、配置的坑

### 5. 端口约定
- PG 默认连 **5432**（`APPBASE_PG_PORT` 可改；代码默认值写的是 5433，别被源码默认值骗了）。
- AppBase 主服务 **3419**（hall + 后端 API，同源）。
- AI 网关 **3418**（Bearer 鉴权）。

### 6. 必需的环境变量（缺了各自的失败表现）
| 变量 | 作用 | 缺失表现 |
|---|---|---|
| `APPBASE_PG_*` 五件套 | PG 连接 | 启动即失败（initAppBackend 连不上库） |
| `BIGMODEL_API_KEY` | LLM 上游 | 页面能开，对话/AI 功能报“该应用尚未配置 LLM” |
| `AGENT_DRIVER=zcode` | 网页应用生成器驱动 | 默认走 codex；用 ZCode 还需 `ZCODE_NODE_BIN`/`ZCODE_CLI_PATH` |
| `APPBASE_GATEWAY_KEY` | 网关鉴权 | 不设则每次启动随机生成打印在控制台 |
| `APPBASE_TOKEN_SECRET` | 登录 token 签名 | 不设则重启后所有登录失效，需重新登录 |

### 7. 关机不自启
PG（pg_ctl 手动挂载）和 AppBase（pnpm start）都没有注册开机自启，重启后需重新拉起。本机用 `examples/appbase/start-appbase.cmd` 一键启动。

## 三、多设备/局域网访问的坑

### 8. 生成的前端应用曾硬编码 127.0.0.1（已修复，注意复发）
teacher-notebook 等 AI 生成应用曾把 API 基址写成 `http://127.0.0.1:3419`，导致其他设备打开页面时请求打到设备自身，表现为“换设备要重新建账号、数据不共享”。
**根治**：生成应用的提示词里明确要求“后端 API 一律用相对路径（空基址），禁止硬编码 127.0.0.1/localhost/内网 IP/端口”。

### 9. 多设备账号语义
- 账号体系是全局的（存服务端 PG `users` 表 / `app_accounts` 表），所有设备共享。
- 每台设备**首次访问需登录一次**（token 存各设备浏览器），用同一账号登录即见同一份数据——不需要重新注册。
- 大厅管理抽屉里「登录」和「注册并登录」按钮并排，手机上容易点错成注册，产生多余账号（误建的可用 SQL 清理：`DELETE FROM users WHERE email='...'`）。

### 10. 局域网/防火墙
服务监听 `0.0.0.0`，但 Windows 防火墙默认拦入站。其他设备访问前需放行 3419（和 3418 如需直连网关）：
```powershell
New-NetFirewallRule -DisplayName "AppBase 3419" -Direction Inbound -Protocol TCP -LocalPort 3419 -Action Allow
```
设备访问地址：`http://<服务器局域网IP>:3419/hall`（本机为 192.168.1.10）。

## 四、其他

### 11. README 中文乱码
Windows 下用非 UTF-8 代码页（cmd 默认 GBK）查看 README.md 会乱码，属显示问题，文件本身是 UTF-8 正常的。

### 12. 服务端口占用
重复启动 AppBase 会因 3419/3418 被占而失败；先停旧进程（`netstat -ano | findstr 3419` 找 PID）再启。

### 13. 迁移到新服务器的最短路径
1. 装 Node ≥20（建议便携版）→ `npm i -g pnpm@9`；
2. 装 Git + 完成一次 Gitea OAuth 登录；
3. 装 PostgreSQL 15，建库 `appbase`（或整体拷贝旧数据目录挂载）；
4. 仓库根目录 `pnpm install`；
5. 设置第 6 条的环境变量，`cd examples/appbase && pnpm start`；
6. 防火墙放行 3419，局域网设备用服务器 IP 访问。
