# ADR-0002 会话超时治理收敛 —— idle 看门狗 + 部分产出保留 · 预算熔断不做

- **状态**：已采纳（2026-10）—— 第 1、2 层已落地；第 3 层（预算熔断）**明确不做**
- **关联**：`packages/dsh-interop/src/session-relay.ts` · `packages/dsh-interop/src/idle-watchdog.test.ts` · `docs/headless-多轮会话调研.md` · `docs/dsh-第三方插件准入清单.md`
- **来源**：长任务被"总时长硬杀"误伤的问题排查。治理分三层：① 硬杀改 idle 看门狗；② 中断保留部分产出；③ 步数/token 预算熔断。

## 1. 背景与问题

原 relay 对 headless 子进程施加**总时长硬杀**：一轮任务无论是否在推进，到点即 `SIGKILL`。
后果是**"忙"被当成"死"**——真正在跑的长任务被误杀，且已产出的内容整段丢弃。

## 2. 决策一：以 idle 看门狗取代总时长硬杀（第 1 层，已落地）

只有当**连续 `idleMs` 内 stdout/stderr 一个字节都没有**时，才判定卡死并 `SIGKILL`；期间任一字节输出即重置计时。

- 阈值：`DSH_RELAY_TIMEOUT_MS`（毫秒），缺省 300_000（5 分钟）；
- 计时器 `unref()`，不阻塞进程退出。

**判据**：把"是否超时"从**任务总耗时**改为**无输出时长**——治的是"卡死"，不是"跑得久"。

## 3. 决策二：中断不丢产出（第 2 层，已落地）

因 idle 被杀的这一路，**保留已产出正文**交给用户，并显式标注未完成：

- 文案明确"本轮未完成（idle Ns 内无输出，判定卡死已中断），以上内容仅供参考"；
- 正文超 `maxReply` 时首尾保留、中间省略；
- **本条不入 transcript**——半截内容不得污染后续对话上下文。

统一了中断语义：**"中断"= 保留 partial + 标注未完成 + 不入上下文**，对用户始终是同一套行为。

## 4. 决策三：不做步数/token 预算熔断（第 3 层，本 ADR 的否决项）

**否决。** 依据是对已安装产物的实际核查，而非偏好：

| 核查对象 | 事实 |
|---|---|
| `dsh-headless` 参数面 | 仅解析任务位参、`--session-id`、`--json`、`--help`、`--profile`。**无任何预算类参数** |
| `@deepseek-ai/dsh-agent-loop` | 全目录 grep `maxSteps\|stepLimit\|maxTurns\|maxIterations\|stepBudget` **零命中**——该配置项不存在 |
| `@deepseek-ai/dsh-token-meter` | 提供 `measure()` 返回用量；全 `index.d.ts` grep `abort\|stop\|throw\|deny` **零命中**。**只计量，不裁决** |

**结论：官方这条通道上不存在预算开关。** 要做，只能在 relay 侧自建执行点（切 `--json` 消费事件流 → 自行记账 → 超限 `SIGKILL`），即**自研一个 dsh 没有的机制**。

否决理由：

1. **收益不成立**：决策一已让"跑得久"不再被杀，卡死由 idle 收割。用户描述的问题已被前两层覆盖，第 3 层没有对应的未解问题。
2. **成本与回归面显著更大**：第 1、2 层改的是**本仓库自己的代码**；第 3 层撞的是**上游能力缺口**，且必须切 `--json`——stdout 从"最终文本"变为 NDJSON 事件流，**`DshRunResult.output` 的既有含义被破坏性改写**。
3. **口径是产品决策而非技术决策**：按步数/token/字符计价？事件流按 `MAX_STRING_BYTES=8KB` / `MAX_EVENT_BYTES=32KB` **截断**，按字符计会失真；按 token 计则需在 relay 侧另行集成计数（headless 子进程与 relay 不共享 `ctx`）。无明确口径就动手，等于替用户做未授权的公共契约变更。

> **原则：不在宿主侧重复建设上游尚未提供的能力，尤其当其实现要求破坏既有公共契约时。**

## 5. 反例约束（防此否决被误读为"超时治理就此封板"）

1. **idle 阈值不是"越长越好"**：调大只延后收割真卡死，不提升吞吐。默认 5 分钟是权衡值，非承诺值。
2. **本 ADR 不否决"可观测性"**：若需求只是**看见**用量（而非据此中断），token-meter 已在依赖内，接入是独立且低风险的工作——与"熔断"是两件事。
3. **失败仍然要静默可查**：relay 的 `[relay] ...` stderr 诊断行属于运维面，不得因收敛而移除。

## 6. 触发信号（缺一不重议，出现即按第 3 层重开）

| 触发信号 | 说明 |
|---|---|
| 出现**真实成本事故** | 单轮失控产生可测量的超额费用，且 idle 看门狗无法覆盖（有持续输出但无价值） |
| 上游补齐预算开关 | `dsh-agent-loop` 或 headless 参数面原生提供 step/token 上限——届时第 3 层降级为"打开开关" |
| 明确的产品口径 | 用户给出计价口径（步数/token/字符）与超限收尾语义，并**书面接受 `--json` 契约变更** |

三者**均未出现**，故第 3 层不做。

## 7. 关联现状快照（2026-10）

- 代码面仅 `session-relay.ts` 一处变更（+66/−15），无 `--json` 改动、无 public 类型改动；第 3 层**零代码落盘**；
- 验证：`session-relay.test.ts` + `idle-watchdog.test.ts` 共 9 用例通过，`tsc --noEmit` 通过；
- `DSH_RELAY_TIMEOUT_MS` 由 relay 宿主进程**启动时读取**——改 env 需重启进程才生效（长驻服务同样）。
