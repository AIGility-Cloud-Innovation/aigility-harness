aigility-harness · 系统架构总览 五域插件底座 + AppBase 产品壳 + DSH 生态 · 2026-09

一句话：aigility-harness 是一套什么都能插的智能体运行底座，AppBase 是它的产品壳。现在框架上挂着的 Codex、LiteLLM、DeepSeek Harness（DSH）都只是验证案例——契约是主体，插件是过客；接口永久不变，实现任意替换。

① 五域插拔架构底座 → 认知 → 行动 → 编排 → 人格，域号＝依赖序（每域只依赖更小域号）；运行时调用经 Capability Seam 扁平化
② 一切皆插件 · DSH 生态内核用 DeepSeek Harness 的 cordis 运行时；官方 dsh 套件按「行」借力（工具/会话/沙箱/压缩…约 60 行能力）
③ 契约永固 · Harness 可替换core 定义家族中立的 HarnessInterop 契约，dsh 只是当前实现；换其他 harness 家族 = 换一个 interop 包，上层无感

InMemoryKernelAdapter原型内核（AppBase 装配用）· bootstrap 按层拓扑排序
py-bridge声明式 Python 插件 · JSON-RPC over stdio · 反向 call_ts_capability（LangGraph / RAG）
基建 + ingressconfig / logging / audit / rate-limit 四件套；边缘入口：hall(:3419) · http-ingress(:3418) · 飞书 · 企微
DSH 生态对齐（契约 → interop → 官方套件） core 的 HarnessInterop 契约（family / versions / mount，家族中立）→ @aigility-harness/dsh-interop 当前实现（官方套件在本工程的唯一落脚点）→ 官方 @deepseek-ai/dsh + dsh-base 0.1.5-rc.2 精确锁定。 官方能力按 cordis.patch.yml 行清单编址（约 60 行：agent 循环 · 工具族 · 会话 · 沙箱审批 · 上下文压缩 · 子代理…）， dshBaseRows() 只读解析成「官方能力目录」（管理页可视化），mountDshRow() 按行装载进运行时； cordisAligned 校验两侧 cordis 为同一物理模块（单运行时保险丝）。 换 harness 家族 = 新增一个 <family>-interop 包实现同一契约，core / 五域 / AppBase 全部无感。 管理入口：/admin → 「DSH 插件」标签 → 官方能力目录 · 设计与路线图见 docs/dsh-生态共建规划.md
